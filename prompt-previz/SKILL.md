# Prompt Previz — 用代码预演检查视频提示词

生成一条视频要花钱、花时间；很多失败在写提示词时就注定了：5 秒塞了 6 个动作、台词每秒 7 个词、24mm 拍脸、两个人隔 2.6 米出拳、镜头跳轴、蓝色光斑挂在暖光灯上、"no high kicks" 反而召唤出高踢腿……

这个 skill 的做法：**先把提示词变成结构化的镜头规格，用代码在"纸面上"把镜头演一遍**，把物理、时间、空间、措辞上的问题在生成前找出来，再用内置模块把提示词改好。

和用户用他们的语言交流；写给模型的提示词正文保持英文（除非用户的生成模型要求中文）。

## 工作流

### 1. 收集输入
提示词（单镜或多镜）、目标模型及单镜最大时长（默认 15s）、比例、有无台词。用户只给一句话需求时，先按模块写出初稿再预演。

### 2. 抽取镜头规格（shot spec）
按 `references/shot-spec.md` 把提示词拆成 JSON：每个镜头的时长、机位（俯视坐标、朝向、焦段、镜头类型、光圈）、对焦点与距离、人物初始站位与移动、节拍（谁、在第几秒、做什么、打谁、打哪）、台词时间段、光源色温、光斑、胶片、表演任务；多镜头加 `axis` 和 `scene_engine`。

规则：
- 提示词没写的物理量，按画面描述**合理估计并在 JSON 里标注 `"_assumed": [...]`**，在报告里告诉用户哪些是估计值。
- 站位用米，俯视平面：x 向右，y 向前；`facing` 为角度，0° = +x，逆时针。
- 原提示词全文放进每个镜头的 `prompt` 字段，脚本会做措辞检查。

### 3. 跑预演
```bash
python3 scripts/previz.py check spec.json -o previz_out --max-len 15
python3 scripts/previz.py lint prompt.txt --style jkd      # 只有一段文字时的快速措辞检查
```
仅依赖 Python 3 标准库。输出 `previz_out/report.html`（俯视走位图 + FOV 楔形 + 180° 轴线 + 节拍/台词时间线 + 问题表）和 `report.json`。把 HTML 交给用户看。

### 4. 解读并修正
按 error → warn → info 处理。对每个问题：说明它在生成时会变成什么样的画面错误 → 去对应模块拿写法 → 改提示词。改完**更新 JSON 再跑一次**，直到没有 error。

最终交付：
1. 问题清单（一句话说清每个问题的后果）
2. 修正后的提示词（可直接复制）
3. 预演报告 HTML

## 检查项速查

| 代码 | 检查 | 去哪个模块修 |
|---|---|---|
| TIME-01~06 | 节拍超时长、节拍过密（>1.25/s）、同一角色动作重叠、台词语速（英文 >3 词/秒、中文 >5 字/秒）、台词超出镜头、超过模型最大时长 | 拆镜 / 删节拍 |
| SPACE-01/02 | 跨 180° 轴线、人物左右位置互换 | 机位 |
| SPACE-03 | 有动作/台词的人物在画框外（按焦段算水平 FOV） | 机位 / 焦段 |
| SPACE-04 | 出拳/踢腿距离超出臂展腿长（可用 `step:true` 表示垫步） | fight |
| SPACE-05 | 人物站位重叠 | 走位 |
| LENS-01 | 35mm 以下拍脸/特写 | anamorphic §1 |
| LENS-02/03 | 要虚化却没写对焦点/距离/光圈；按薄透镜算景深，背景其实在景深内 | anamorphic §2 |
| LENS-04 | 写了变形镜头却没写椭圆光斑 | anamorphic §3 |
| LIGHT-01~04 | 蓝色拉丝光斑挂在暖光源、画内无亮光源却有光斑、胶片平衡与光线不匹配 | anamorphic §3–4 |
| TEXT-01 | 否定句（named = summoned）| 改成正向描述 |
| TEXT-02/03 | 情绪副词、面部动作编排 | acting |
| TEXT-04 | 品牌/器材厂商名 | anamorphic（描述外观而非品牌）|
| TEXT-05/07 | 武术术语进正文、高踢/转身踢 | fight |
| ACT-01~05 | 说话的人没有表演任务、任务缺项、缺防呆眼安全句、倾听者没任务 | acting |
| FIGHT-01~05 | 高位踢、没有截击、出招超过 4 次、没有静止节拍、缺 FIGHT STYLE LOCK | fight |
| ENGINE-01~05 | 缺目标/障碍、反转没有观众评价转变（INERT）、整段无反转、失败战术不返回信息 | scene-engine |

脚本只能查"可计算"的问题。**脚本跑完后还要人工过一遍**：画面里的东西是否有理由存在、每个节拍的反应方向是否符合打击方向、台词所在的戏是否有统一的场景方向。

## 模块（按需读取）

| 模块 | 什么时候读 |
|---|---|
| `references/modules/anamorphic.md` | 电影感/变形宽银幕/虚化/光斑/胶片质感；修 LENS、LIGHT、TEXT-04 |
| `references/modules/acting.md` | 有台词、情绪节拍、人物眼神死/表演过火；修 ACT、TEXT-02/03 |
| `references/modules/fight/fight.md` | 打戏（截拳道默认，咏春可选）；修 FIGHT、SPACE-04、TEXT-05/07。它会指向同目录下的招式库与套路 |
| `references/modules/scene-engine.md` | 写场景、审剧本结构（目标/障碍/战术/反转/价值转变）；修 ENGINE |
| `references/shot-spec.md` | 写 JSON 前必读 |

## 原则

- 模型听的是**画面证据**，不是名词：写"椭圆形竖向光斑在湿地面上"，而不是"变形镜头感"。
- 一个镜头一个机位、一个焦段；动作给足时间（每个动作 1–2 秒）。
- 不要用否定句排除东西，写你要的正向状态。
- 预演结论要落到具体改法上，不要只罗列问题。
